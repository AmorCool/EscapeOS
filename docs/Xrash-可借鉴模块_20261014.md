# Xrash 可借鉴模块（用于 TequilaDash 的「更多 - 崩溃分析」）

- 来源：`owngoal-dev/Xrash`（Swift，7 star）
- 自述：Crash reporter and symbolicator for custom firmware iOS 15+
- 调研日期：2026-10-14

---

## 一、TequilaDash 现在有什么

| 现有文件 | 作用 |
|---|---|
| `TequilaDash/Engine/CrashLogService.swift` | 从设备拷崩溃报告 |
| `TequilaDash/Views/CrashLogView.swift` | 崩溃日志列表 / 查看 |
| `rust/idevice-ffi/src/crashreportcopymobile.rs` | FFI：`crashreportcopymobile` 服务 |

也就是：**能把崩溃报告拉下来、能看**。缺的是「看懂」—— 报告是一堆地址，
没有符号化就只是天书。

---

## 二、Xrash 里值得拿的东西（按优先级）

### P0：报告文本查看器（带搜索）

| Xrash 文件 | 拿什么 |
|---|---|
| `Interface/Viewer/ReportTextViewController.swift` | 报告全文查看页 |
| `Interface/Viewer/SearchableTextView.swift` | 可搜索的文本视图 |
| `Interface/Viewer/FindBar.swift` | 查找条（上一个/下一个/高亮） |
| `Interface/Viewer/ReportTextSearch.swift` | 搜索逻辑（匹配 + 定位） |

**为什么是 P0**：崩溃报告动辄几千行，找 `Exception Type` / `Thread 0 Crashed`
全靠搜索。现在的 `CrashLogView` 是纯列表，看全文没有搜索能力。

### P0：dSYM 符号化

| Xrash 文件 | 拿什么 |
|---|---|
| `Services/DSYMImport.swift` | 导入 dSYM 文件 |
| `Interface/Symbols/SymbolListViewController.swift` | 符号列表 |
| `Interface/Symbols/SymbolsViewController.swift` | 符号管理页 |
| `Interface/Symbols/GitHubReleasesViewController.swift` | 从 GitHub Release 拉符号 |
| `Services/GitHubReleaseSymbols.swift` | 拉符号的网络层 |

**为什么是 P0**：没有符号化，`0x0000000102a3f4c0` 永远只是地址。
符号化后才能显示 `-[AppDelegate application:didFinishLaunchingWithOptions:]`。

### P1：语法高亮（堆栈 / 寄存器着色）

| Xrash 文件 | 拿什么 |
|---|---|
| `Interface/Viewer/ScaledEditorTheme.swift` | 编辑器主题 |
| `Packages/Runestone/`（整个包） | iOS 代码编辑器（Tree-sitter 语法高亮） |

**注意**：Runestone 是一个完整的 SwiftPM 包，体量不小。
如果只是为了「给堆栈行着色」，可以只做轻量版（按行首正则上色），
不必整个引入。

### P1：报告导出与归档

| Xrash 文件 | 拿什么 |
|---|---|
| `Services/ReportPDFRenderer.swift` | 导出 PDF |
| `Services/ReportBundleBuilder.swift` | 打包（报告 + 符号 + 设备信息） |
| `Services/ReportLibrary.swift` | 报告库（历史管理） |
| `Services/SavedBundleStore.swift` | 存档 |

### P2：可直接复用的 UI 组件

| Xrash 文件 | 用途 |
|---|---|
| `Interface/Shared/EmptyStateView.swift` | 空状态（「还没有崩溃报告」） |
| `Interface/Shared/ProgressCard.swift` | 进度卡片 |
| `Interface/Shared/CollapsibleSectionHeaderView.swift` | 可折叠分区头 |
| `Interface/Shared/SectionedTableDataSource.swift` | 分区表格数据源 |
| `Interface/Shared/SelectionTableViewController.swift` | 选择型表格 |
| `Interface/Shared/SheetNavigationController.swift` | 弹窗导航 |

这些和「崩溃分析」没有强绑定，但 UI 观感确实好，可以顺手用在别处。

### P2：守护进程（崩溃即时通知）

| Xrash 文件 | 用途 |
|---|---|
| `xrashd/DaemonServer.swift` | 常驻服务 |
| `xrashd/NoticePoster.swift` | 崩溃时发通知 |
| `xrashd/ReportAnnouncer.swift` | 报告广播 |
| `xrashd/PeerAuthenticator.swift` | 对端鉴权 |

**注意**：TequilaDash 是侧载 App（非越狱守护进程），
这套 `xrashd` 依赖 rootful/rootless 环境，**能拿的是思路不是代码**。

---

## 三、建议的落地顺序

1. **给现有 `CrashLogView` 加「全文查看 + 搜索」**（改动最小、收益最大）
   - 参考 `FindBar` + `SearchableTextView` 的交互
2. **加 dSYM 导入 + 符号化**
   - 这一步做完，「崩溃分析」才真的能分析
   - 可以先用 `atos` / `symbolicatecrash` 思路在本机做（App 内做要自己解析 Mach-O）
3. 堆栈行着色（轻量正则版，不引 Runestone）
4. 导出 PDF / 打包（方便发给别人看）

---

## 四、结论

Xrash 最值得抄的是**两块**：

1. **带搜索的报告查看器**（`Interface/Viewer/` 四个文件）
2. **dSYM 符号化链路**（`Services/DSYMImport.swift` + `Interface/Symbols/`）

其余（Runestone 编辑器、xrashd 守护进程、UI 组件）属于锦上添花，
其中 `xrashd` 因为运行环境不同，只能参考思路。
